# Companion comparison captures

These distinguish the **selected HTML direction** from the **implemented native SwiftUI views**. Native captures include Marc’s subsequent density review: a compact home header, filtered fights, smaller detail artwork and a separate Share tab. Existing native product behavior wins over the prototype's simplified interactions. In particular, native Feed does not invent illustration posts, and your chosen companion replaces your local avatar; other accounts still use their saved photos/initials until account-backed companions exist.

Both native folders include **both themes**, Current / Invited / Past lists, Share, the post composer, all eight chart modes, invitation, History, tied, solo, deferred, pending, finished, empty and loading states. Files ending `-large-text.png` render Fights, group detail, New, You and picker at Accessibility 3. The picker is scrollable; its confirmation button follows the grid, and the tennis artwork study follows confirmation.

Native captures are 393 × 852 PNGs, generated by `ScreenshotExport.exportCompanion()` on iOS 26.5 using the real views. They omit system status icons. The top preview banner has been removed at Marc’s request; controls live under You → Companion preview. These are static view renders, not evidence that a real account or Health sync was exercised. The running Simulator was separately inspected at its own size.

Prototype captures came from the retained [self-contained HTML](../../kit/companion-app-proposal.html), served locally in Safari. The prototype phone is 393 × 852 CSS points, displayed at browser zoom, cropped from the visible browser screenshot and resampled to the 393 × 852 comparison canvas. The prototype picker is a standalone centered dialog; its full dialog is letterboxed onto that canvas rather than presented as a native sheet capture. Browser screenshot compression is retained in these references.

For launch instructions, checks and the review gate, see the [Simulator handoff](../../../companion-simulator-handoff.md).

Some static Feed captures omit reaction chips; their rendering and the repositioned post-actions button were checked in the running Simulator.
